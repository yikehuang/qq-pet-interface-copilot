# QQ Pet Interface Copilot / QQ 宠物接口助手

中文：一个正在验证中的电脑端 QQ 宠物自动控制工具。当前版本只使用 Android 手机 QQ 协议，通过本机模拟器中的已登录手机 QQ 调用宠物 OIDB 接口；调度器不会连接或回退到 NapCat/OneBot。

English: A PC-side QQ pet automation assistant under active validation. The current version exclusively uses the Android QQ mobile protocol through a logged-in QQ instance in a local emulator; the scheduler never connects or falls back to NapCat/OneBot.

> 中文：当前仓库用于展示阶段性成果，处于公开预览阶段。请只操作自己的 QQ 账号，并自行承担非公开接口发生变化的风险。
>
> English: This repository is a public preview of work in progress. Use it only with your own QQ account and accept the risk that undocumented interfaces may change.

操作台提供“一键导出脱敏诊断包”：仅收集运行环境、非敏感设置摘要、接口目录及筛选后的错误日志。QQ 会话、账号、petId、好友列表、密码、Token、Cookie 和原始封包不会被收集，诊断包也不会自动上传。

如需提交问题，可先导出诊断包，检查内容后再附加到 GitHub Issue。默认不做后台遥测；若以后启用自动回传，应使用由项目维护者控制的私有 HTTPS 接收服务和每位用户独立的撤销密钥，不能把仓库写入 Token 固定在客户端中。

## 重要变更：NapCat 宠物接口失效，切换 Android 手机规则版

当前版本已经停用 NapCatQQ、OneBot 和电脑版 QQ 封包链路，状态读取及任务写入统一改走本机 Android 模拟器或 USB 手机中的 QQ 协议。NapCat 的 Native 层实际上能够收到服务器回包；修复其空回包交接后，服务器返回的真实原因是 `errorCode=319`、`[oidb] rule type not match appid`。这表示服务器拒绝电脑版 QQ 会话的 AppID/规则类型，不是 `petId` 错误或 OneBot 掉线。

本机日志显示，2026-08-11 16:03:55（北京时间）仍能完成真实学习结算，16:07:15 起同一读取命令持续失败；最窄观测窗口为 **16:03:55—16:07:15**。这只代表已观测账号/线路，服务器可能采用灰度策略。完整技术说明见 [NapCat QQ 宠物接口失效说明](docs/napcat-appid-policy-20260811.md)。

调度器在手机协议连接失败时只进入重连，不会静默回退到 NapCatQQ，也不会重复发送结果不确定的写指令。

NapCatQQ 相关兼容代码可能暂时保留在历史模块中，方便旧版本对照，但一键启动器、设置页面和自动调度器均不再安装、启动或调用 NapCatQQ。

## 调度逻辑

### 动态收益优化

完整的两种调度模式、计算目标和切换方法见 [调度机制说明 / Scheduler Modes](docs/scheduler-modes.md)。

设置页保留原来的金币阈值、课程和岗位调度，并新增独立的“测试：启用动态数学模型调度”开关，默认关闭。关闭时完全沿用原调度；只有主动开启后，助手才会在每次准备开课或开工时重新读取服务器当前课程与岗位目录，并综合计算课程属性收益、学费、岗位金币、任务时长、体力与清洁消耗，以及恢复这些状态所需的饼干和香皂成本。目标是在期末金币不低于安全线、并可选择补回当天开始金币的前提下，让当天学习收益最大。

学习与打工共用累计时长，模型按 0–8 小时 100%、8–12 小时 25%、12–24 小时 10% 的疲劳区间计算。服务器目录已经显示当前疲劳档收益时，程序会先还原基准值再推算后续区间，避免重复打折。课程升级、岗位开放状态或服务器奖励变化后，下一次决策会重新搜索，不依赖写死的课程或岗位。

默认资源参数来自当前实测：学习消耗体力 10/清洁 4，打工消耗体力 4/清洁 2；饼干 5 金币恢复 10 体力，香皂片 2 金币恢复 10 清洁。这些参数均可在设置页调整。

- 体力或清洁低于默认阈值 80 时，优先照顾宠物；库存不足可自动用金币补货。
- 自动照顾可分别选择饼干或虾仁喂食，也可选择香皂片或沐浴球洗澡。食物数量以服务器食物目录的实时余额为准；虾仁使用服务器下发的 `foodId`，洗护用品使用对应 `itemId`。当前金币购买接口只验证了饼干，虾仁不足时不会误发饼干购买封包。
- 自动 PK 到达配置时间后启动一次“每日批次”，在同一批次内按每日上限完成挑战；默认从服务器好友宠物池中选择对手，单个好友连续成功 3 次后自动切换下一位。批次结束会写入当天完成标志，停止或重启调度不会再次开启。体力或清洁不足时先暂停，自动照顾后再继续。
- 自动 PK、手动 PK 与好友照顾属于旁路任务：学习、打工或冒险在服务器倒计时期间仍可执行；请求在本地依次发送，避免同一动作重复提交。
- PK 每日成功、失败、金币收益、storyId 和批次完成状态写入 `runs/pk-日期.json`，未完成批次可恢复，已完成批次当天不再重复，第二天自动使用新文件。
- 配置时间后优先尝试冒险。
- 金币充足时优先学习，否则尝试打工。
- 学习会读取服务器当前学园阶段和实时课程目录，按力量/智力/魅力优先选择当前可执行的最短时长课程，再调用真实开课接口；年级升级导致固定课程失效时会自动刷新、改选并恢复自动模式。
- 设置页可刷新当前阶段课程，选择“自动最短时长”或固定某一门课程，保存后下一轮立即生效。
- 打工会逐个探测服务器职业记录并隔离资格不足的职业，部分职业未解锁时仍保留其他真实可执行岗位；自动模式优先选择最短时长岗位，也可以在前端固定职业与岗位。固定岗位失效时会自动刷新并回退。开工使用职业模块的真实 `6400` 请求。
- 学习或打工启动并取得 storyId 后会调用手机端真实“鼓励宠物”接口；成功记录按天持久化，同一任务不会重复鼓励。
- 打工雇佣支持“自动选择可用好友”和“手动选择固定好友”。好友来自服务器下发且已确认 petId 的宠物好友池，并排除登录账号自身；手动选择会同时保存好友 QQ 与真实 petId。
- 冒险会读取服务器实时天气/事件选项（例如“晴天”或“阴天”），只选择服务器当时标记为可执行的项目，再调用真实 `6700` 开始接口。
- 设置页可以刷新并固定服务器返回的冒险选项，不再使用写死路线；学习、打工、冒险均为互斥主任务，服务器已有其中一项倒计时时不会启动另外两项。
- “设置 → 接口测试”进入时会自动加载服务器目录，并提供状态读取、全部目录检查以及喂食、洗澡、学习、打工、雇佣好友开工、冒险和被雇佣召回的单次测试。目录检查是只读操作；带“真实测试”字样的按钮会立即消耗所选服务器道具、启动任务或提前召回，并在操作后重新读取状态验证是否真正生效。
- 食物测试按服务器下发的 `foodId` 选择具体物品；若服务器只返回虾仁总数而未下发虾仁 `foodId`，界面会明确提示并禁止猜测封包。
- 任务完成后按 `storyId` 结算并持久化，避免对旧任务反复结算。
- 手机 QQ 协议连接超时后自动进入重连状态，默认从 3 秒开始指数退避、最长等待 60 秒；恢复后继续下一轮，不会重发刚才可能已经送达的写指令。
- 普通操作反馈使用不阻塞界面的应用内彩色消息；主任务连续失败达到阈值后，可通过“外部通知”发送 Windows 系统通知、Bark、PushPlus、Server酱、SMTP 和自定义 Webhook，支持重复发送冷却、恢复通知和界面内测试发送。

## 当前限制

- 好友雇佣的开工字段已经恢复，但服务器尚未返回可用雇佣列表，因此自动选择好友仍未完成；无好友时会按正式协议正常开工。
- 好友访问使用服务器当前下发的 `1000/100/*` 动态路径，不再循环历史抓包对象；每天只处理当前 QQ 好友，失败对象独立记录且当天不频繁重试。`0x96a6_1` 按手机 QQ 的实现允许空业务回包，但必须在发送后重新读取目标好友页面才能记为成功；“踩踩”仍作为访问成功后的独立可选操作。
- 自动 PK 已实现服务器好友宠物池分页读取和轮换；手机协议若对好友池命令返回空包，会明确记录并临时使用已验证的备用对手，不会把空成功码误报成“已读取全部好友”。
- “PK 好友”独立页面支持按 QQ 好友名选择或直接输入 QQ 号，自动解析真实 petId、好友备注和实时战力；可自定义连续 PK 1–99 场，手动结果不会写入自动 PK 的每日轮换进度。
- PK 与好友照顾的好友选择框会把已确认有宠物的好友排在最前，并可隐藏服务器确认无宠物的好友；接口临时不可用时保留“宠物资料未知”对象，避免错误排除。
- “好友照顾”页面可维护独立监控名单；默认每 60 秒读取名单内好友体力，低于 80 时自动喂食。失败好友进入独立冷却，成功必须重新读取好友体力确认上涨，并计入每日好友喂食次数。
- 被雇佣召回支持“等到 25/75（收益分成最高）”和“立刻召回”两种策略；召回使用服务器结算回包验证、按 storyId 去重并写入每日计数。
- 打工设置可启用“自动雇佣好友”；开工前优先读取服务器好友宠物池并选择可用好友，好友池暂时为空时可使用已验证的备用好友，缺少可靠 petId 时才无好友开工。
- 冒险奖励由服务器在结算时决定，目录可能只给出事件描述而不提前显示奖励。
- 项目依赖本机 Android 模拟器和已登录的手机 QQ，尚不是独立 QQ 登录客户端；模拟器与 QQ 必须保持运行。

## 快速开始

### 一键更新

一键启动窗口和主控制台左侧均提供“检查更新”按钮。程序只检查本项目 GitHub Releases 的最新正式版；发现新版后可一键下载，并核对 GitHub Release 提供的文件大小和 SHA-256。Windows 打包版会退出当前程序、保留一个 `.previous.exe` 旧版备份、替换新版并自动重新打开，且不会覆盖 `config.yaml` 和 `runs/`。源码运行模式只检查和下载，不会自动覆盖开发目录。

### 一键启动（Windows）

双击 `start-interface-copilot.bat`，启动器会依次完成：

1. 检查 Microsoft VC++ 2015–2022 x64 必备运行库；缺失时只从 Microsoft 官方地址下载，验证 Authenticode 数字签名后静默安装。
2. 自动查找 MuMu、雷电模拟器或 Android 平台工具中的 ADB，并选择当前运行的模拟器实例或已连接的 USB 手机。
3. 检查手机协议组件；缺失时从 Frida 官方 Release 下载固定版本，完成 SHA-256 校验后安装并启动。
4. 从模拟器中已登录的手机 QQ 读取当前账号和宠物资料。
5. 验证宠物状态后保存本机配置并打开控制台。

Release 中的 `QQ宠物助手.exe` 已内置 Python、Tcl/Tk 图形界面、HTTPS/证书、加密、OnePush 和 Frida 客户端依赖，普通用户不需要另外安装 Python 或执行 `pip install`。当前版本已支持自动识别 MuMu 和雷电模拟器，也保留 USB Android 设备连接；目标设备必须提供 ADB Root，并保持设备和已登录的手机 QQ 运行。

首次接入时，启动器会通过模拟器中的手机 QQ 调用本人资料接口，直接从服务器读取并校验 `petId`，随后自动保存。启动器不会导出 QQ 会话，也不会把会话数据上传到网络。

NapCat、OneBot 和 SnowLuma 均不属于当前运行链路，启动器不会下载、安装或启动它们。

也可以下载 GitHub Actions 生成的 `QQ-Pet-Interface-Copilot-Windows-x64.zip`，解压后直接运行 `QQ宠物助手.exe`。

### 开发者启动

准备已登录目标账号的 Android 模拟器手机 QQ 和协议桥，使用 Python 3.11+ 运行：

```powershell
py -3 launcher.py
```

首次接入新账号时建议保留安全模式，确认状态读取正常后再开放写操作。

## 运行流程

```text
模拟器中的手机 QQ 登录
      ↓
手机协议桥连接 QQ 进程
      ↓
一键启动器读取账号与宠物 ID
      ↓
QQ 宠物助手读取服务器状态和动态规则
      ↓
统一调度器执行照顾、学习、打工、冒险和 PK
      ↓
重新读取服务器状态验证结果，并写入 runs/ 每日进度
```

本项目不包含 QQ 或模拟器。手机协议服务端组件仅在首次接入时从 Frida 官方 Release 下载并校验，不进入仓库。GPL-3.0-only 只覆盖本仓库代码；QQ、模拟器与 Frida 分别遵循其自身许可和使用条款。当前版本运行时需要可用的 ADB Root 调试连接。

## 开发进度与后续计划

当前后续工作主要集中在仍缺少真实服务器数据验证的 **好友雇佣链路**：

- 继续验证服务器返回的真实可用好友雇佣列表及相关字段；
- 在服务器返回可用雇佣对象后，验证好友雇佣后的真实开工、倒计时和收益结算流程。

在服务器没有返回真实可用数据之前，项目不会通过伪造数据、写死接口返回值或仅根据成功码宣称功能已经完成。所有标记为“已验证”或“已跑通”的功能均以真实 Android QQ 会话中的服务器状态变化作为判断依据。
